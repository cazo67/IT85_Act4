# Documentation Guide

Use these documents in this order when preparing or demonstrating BCIS:

1. `user-manual.md` — operator workflows and current limitations.
2. `technical-overview.md` — architecture and responsibility boundaries.
3. `erd.md` — entity relationships and financial-history model.
4. `architecture/financial-invariants.md` — rules that protect balances and history.
5. `deployment/windows-lan.md` — Windows server/client setup and recovery procedure.
6. `../tests/acceptance/AT-01-AT-12.md` — acceptance status and evidence still required.
7. `../tests/acceptance/demo-checklist.md` — live demonstration sequence.
8. `defect-log.md` and `release-notes.md` — release readiness and known gates.

Phase verification records under `architecture/` separate automated evidence from checks that require PostgreSQL, installed clients, printers, or multiple physical PCs.
